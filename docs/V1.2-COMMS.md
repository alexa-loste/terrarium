# Terrarium v1.2 — async communication (the Feed + direct messages)

Give the town ways to communicate **without being face-to-face**: a public "internet" feed
where they publish posts / "research", and direct messages / pings between any two people.

## The one principle that makes this work

In *Generative Agents: Interactive Simulacra of Human Behavior* (Park et al., 2023) there is
no messaging app — yet news still spreads (Sam's mayoral run reached 4%→32% of agents,
Isabella's party 4%→52%). It spreads because **every perceived event is written to the
memory stream**, and memory drives retrieval → reflection → planning → dialogue. Nothing is
a special "comms channel"; it's all observations.

So our rule: **a feed post or DM is delivered by writing an observation into each recipient's
memory stream.** The transport tables + UI are just plumbing; behavior changes because the
text becomes a memory and gets retrieved later. This reuses, unchanged:

- `convex/agent/memory.ts` → `insertMemory` (embeds + stores), `calculateImportance` (LLM
  1–10 poignancy), `searchMemories` (recency decay 0.995 · importance · relevance, the
  paper's exact recipe), and the reflection trigger (importance-sum threshold).
- `convex/agent/conversation.ts` → memories already get injected into dialogue prompts via
  `relatedMemoriesPrompt`. A salient post/DM will surface there for free.

Granularity we inherit from the paper by doing this: a juicy post (a "research breakthrough",
a dramatic news event) gets a HIGH importance score → more likely to be retrieved AND to push
an agent over the reflection threshold → reshapes what they think and say. A mundane post
fades. We don't hand-tune that; importance scoring does it.

## Build order (each step ships + tests independently on the Mini)

Ordered simplest→richest. Steps 1–2 already deliver "manual world events" for free (an event
is just a post authored by "the news").

### Step 1 — Feed substrate + UI  *(no agent behavior yet; lowest risk)*
The public board exists and is visible; **alexa** can post to it (incl. as "the news").
- **Schema** (`convex/schema.ts`, new table): `feedPosts`
  `{ worldId, authorPlayerId: v.union(v.id-ish, v.null()), authorName, kind: 'post'|'research'|'news', text, createdAt }`
  (authorPlayerId null = world/news/alexa).
- **Functions** (`convex/aiTown/feed.ts`, new): `postToFeed({worldId, author, kind, text})`
  mutation; `listFeed({worldId, limit})` query (reactive, newest-first).
- **Frontend**: a `<Feed>` panel (a tab in the right column, or a toggle like the roster) that
  lists posts; a text input so alexa can post as herself OR pick "📰 The News" to inject a
  world event. (This *is* the manual-events feature from V1.1-WORLD §Chunk E.)
- **Test**: alexa posts → it appears, persists, survives refresh.

### Step 2 — Perception: agents ingest feed posts as memories  *(behavior starts here)*
New posts become observations in every agent's memory stream, so they influence later talk.
- **Delivery**: a `rememberObservation(ctx, agentId, text)` thin wrapper over the existing
  `calculateImportance` + `fetchEmbedding` + `insertMemory` path, with a new memory `data`
  variant `{ type: 'feedPost', postId }` (add to the union in `convex/agent/schema.ts`).
- **Fan-out + dedupe**: per-agent "last seen feed cursor" (a `feedSeenAt` field on the agent,
  or a tiny `feedSeen` table). On each agent tick (or when a post is created), ingest any
  posts newer than the cursor as observations: `"On the town feed, {author} posted: {text}"`.
- **Prompt**: nothing new needed — ingested posts ride the existing `relatedMemoriesPrompt`.
- **Test**: alexa posts a provocative "news" item → within a few ticks agents reference it in
  conversations near the relevant places.

### Step 3 — Production: agents publish to the feed
Agents occasionally write their own posts / "research", driven by identity + recent memory.
- **Loop**: a new branch/activity in `convex/aiTown/agentOperations.ts` (`agentDoSomething`)
  or a dedicated `agentMaybePost` operation, gated by a cooldown (e.g. ≤1 post / sim-hour /
  agent) so the feed isn't spam.
- **Generation**: an LLM call prompted with the agent's first-person identity + plan + top
  retrieved memories → a short post. Bias `kind:'research'` for the `hasAgent` folks
  (Mara/Priya/Naomi) — this is the natural hook for the future human↔AI agent loop (Chunk D).
- **Cost note**: each post = 1 local-model (or API) call. Log a per-tick gate; watch Mini load.
- **Test**: leave it running; the feed populates with in-character posts.

### Step 4 — Direct messages / pings  *(async, cross-map — the diffusion accelerator)*
One agent messages another regardless of distance; delivered to the recipient's memory.
- **Schema**: `directMessages` `{ worldId, fromPlayerId, toPlayerId, text, createdAt, readAt }`.
- **Functions**: `sendDirectMessage(...)`; `listInbox({worldId, playerId})`.
- **Delivery**: same observation trick — write `"{from} messaged you: {text}"` into the
  recipient's memory (`data.type:'directMessage'`). Now news jumps across town without
  co-location (the paper's diffusion, unshackled from physical proximity).
- **Production**: an agent occasionally DMs someone they already have memories about
  (retrieval-driven recipient pick → relationship-aware, like the paper).
- **Frontend**: a small inbox in `PlayerDetails` for the selected character; (optional) let
  alexa DM as a character to nudge the sim.
- **Test**: trigger a DM (alexa-sent first), confirm recipient references it later elsewhere.

### Step 5 — Threads / reactions  *(richest; emergent discourse — optional)*
Replies turn the feed into a threaded groupchat; agents argue.
- **Schema**: add `replyToId` to `feedPosts`.
- **Loop**: when an ingested post is relevant + high-importance to an agent, they may reply.
- **(Optional)** lightweight agree/disagree reactions that update relationship memories.
- **Risk**: emergent loops + cost; gate hard. This is where SF-2026 debates actually happen.

## Ordering rationale & dependencies
- **1 → 2** is the spine: board + perception. After step 2 the world already *feels* connected
  and you get manual events for free.
- **3 and 4** are independent of each other; do whichever you want to see first (3 = a living
  feed; 4 = cross-map gossip).
- **5** wants 3 in place.
- Mostly **independent of the clock (Chunk B)** and the **human↔AI loop (Chunk D)** — but step
  3/5 get richer once agents have *plans* (posting becomes a planned act, not random) and once
  `hasAgent` people can have their AI literally draft the "research". Natural convergence point.

## Paper-granularity notes (tuning, parallel track)
- **Reflection threshold**: code comment in `memory.ts` says reflect when latest-100 importance
  sum > 500; the paper uses **150** (≈2–3 reflections/day). If big posts should reshape agents,
  tune this down toward the paper's value.
- **Importance is the salience knob**: we get "big news propagates, small talk fades" for free
  because `calculateImportance` scores each observation 1–10 before it enters memory.
- **Relationship memory**: DMs + replies naturally write per-other memories, which is how the
  paper forms relationships (Maria→Klaus). No extra structure needed.
