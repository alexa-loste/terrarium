# Terrarium v1.1 — a realistic world (build spec)

Goal: turn the toy town into **San Francisco, 2026** — eight people with real lives and
nuanced AI leans, places they go, things they do, a clock and calendar, world events that
break over time, and AI agents that a few of them work with (human↔AI only for now;
agent↔agent later).

This doc is the build spec + the exact integration seams (from a codebase map). It splits
into **content (shipped, safe)** and **mechanics (chunks to land on the Mini with you
testing each)** — because the mechanics touch Convex schema + the engine, which can't be
verified from the Air without risking your working boot.

## Mechanics — build chunks (land one at a time, test on the Mini)

Each chunk lists the **seam** (file + function) so it's a surgical change. Order chosen so
each is independently testable and the world is never broken between chunks.

### Chunk A — richer character fields *(schema)*
Add `role`, `projects`, `aiLean`, `hasAgent` as first-class fields (instead of packing into
identity), so mechanics can read them.
- **`data/characters.ts`** — add the fields.
- **`convex/aiTown/agentDescription.ts`** — add to `serializedAgentDescription` schema + constructor.
- **`convex/aiTown/agentInputs.ts`** (`createAgent` handler) — pass fields through to `new AgentDescription`.
- **`convex/agent/conversation.ts`** (`queryPromptData` → `agentPrompts()`) — inject into prompt.
- ⚠️ Convex schema change → push carefully; wipe/reseed the world if needed.

### Chunk B — clock + calendar *(engine)*
Sim time-of-day + day counter, exposed to prompts.
- **`convex/aiTown/game.ts`** — add `dayCounter` + `timeOfDay`, advance in tick from `engine.currentTime`.
- **`convex/constants.ts`** — `HOURS_PER_SIMULATION_DAY` (accelerate), phase boundaries.
- **`convex/agent/conversation.ts`** — add `It's {timeOfDay}, day {dayCounter}` to the prompt.
- Frontend (optional): show day/time. Enables time-of-day behavior (work by day, bar at night).

### Chunk C — places *(schema + nav)*
- **`convex/aiTown/schema.ts`** — `places` table (name, x, y, radius, type, description).
- **Seed** from `data/places.ts` in `convex/init.ts`; set real `x/y` against the map.
- **`convex/aiTown/agentOperations.ts`** (`agentDoSomething` / `wanderDestination`) — pick a
  place that fits the agent's goal instead of a random tile.
- **`convex/agent/conversation.ts`** — add "you're at {place}" to context.

### Chunk D — the AI agent (human↔AI work loop)  ⭐ the heart of it
The non-embodied agent. NOT a sprite. A capability some humans have.
- **Data:** mark `hasAgent` humans (Mara, Priya, Naomi) + give each an agent name + the
  provider/model it runs on (Claude / GPT / DeepSeek — **per-agent chat model**; see
  DESIGN.md embedding-uniformity rule).
- **`convex/util/llm.ts`** — fork the global provider switch into a **per-call model override**
  so an agent can run on a different chat model than the human-substrate.
- **New activity "working with their agent"** (Chunk-A `ACTIVITIES`/LLM-decided): when a
  `hasAgent` human does it, run a short human→agent→result exchange:
  human poses the task (from their `projects`) → the agent model answers → the result is
  written to the human's **memory** (`rememberConversation` in `convex/agent/memory.ts`) and
  nudges their project forward. Visible as a status + (optional) the "cloud" zone lighting up.
- Short-term: agent only ever talks to its human. **No agent↔agent yet.**

### Chunk E — world events injection *(content → memory)*
- On each new sim-day (Chunk B), take that day's `data/events.ts` entries and inject them as
  a memory / "news" line for every agent (write via `rememberConversation` or a lighter
  `insertMemory`), so the town perceives and discusses them.
- **`convex/agent/conversation.ts`** — surface "recent news: {headline}" in context.
- This is what makes the world feel alive and gives characters something to disagree about.

### Later — agent↔agent, agent spawning
Once Chunk D is solid, let agents message each other (still mediated/observable), then spawn
sub-agents. These are the "AI-development directions" tech-tree flags from DESIGN.md.

## M4 / cost reality (unchanged truths)
- Humans on **local Ollama** (one model, serialized) → **more humans = a slower world.**
  8 humans is fine for an *ambient* sim; if it crawls, comment some out or shrink the model.
- The **AI agents call real APIs** (Claude/GPT/DeepSeek) — fast, and they don't bottleneck
  the local model. Cheap (DeepSeek especially), but it *is* live spend per agent action.
- Keep prompts short: identity ~5 sentences, `NUM_MEMORIES_TO_SEARCH` low, event headlines short.

## Suggested build order
**A (fields) → B (clock) → E (events) → C (places) → D (AI agent).**
Rationale: A+B+E together make the *humans* feel like they live in a moving world (fast win,
mostly prompt-context). C adds spatial life. D is the showpiece and benefits from all of it.
(If you'd rather see the AI loop first, D can jump the line — it only strictly needs A.)
